# i18n message standard

Catalogs live in `src/i18n/<locale>/<namespace>.json`. nestjs-i18n maps **filename → first key segment** (`errors.notFound`, `auth.errors.login`). Types are generated in `src/generated/i18n.generated.ts` — use `I18nService<I18nTranslations>` (or `I18nPath`) so typos fail at compile time.

## Files

```text
src/i18n/
  en/
    common.json       # truly shared strings only
    errors.json       # generic HTTP / Prisma fallbacks
    validation.json   # class-validator templates
    auth.json         # one file per Nest module
    users.json
  hi/                 # same filenames and keys as en/
```

- Keep catalogs in `src/i18n/`, not under `src/modules/`.
- Add `src/i18n/en/<module>.json` in the same PR as a new Nest module.
- New locale: copy the full `en/` tree. Do not add files piecemeal.
- If a module file exceeds ~50–80 keys, nest groups **inside** it. Do not create `users-errors.json`.

## Key shape

```text
{namespace}.{group}.{intent}
```

| Segment | Meaning | Example |
|---|---|---|
| `namespace` | JSON file = Nest module | `auth`, `users` |
| `group` | kind of message | `errors`, `success`, `emails` |
| `intent` | stable meaning, not English copy | `invalidCredentials` |

```json
{
  "errors": {
    "invalidCredentials": "Invalid email or password"
  },
  "success": {
    "login": "Signed in successfully"
  }
}
```

```ts
this.i18n.t('auth.errors.invalidCredentials');
this.i18n.t('orders.success.created', { args: { id } });
```

Call `t()` in filters and for returned copy. HTTP exceptions store the key (rule 7).

**Casing:** camelCase for app keys (`notFound`). SCREAMING_SNAKE only for validation keys that match class-validator (`IS_EMAIL`, `MIN_LENGTH`). Locales are BCP 47 folders (`en`, `hi`).

**Depth:** 2–4 segments. `users.errors.emailTaken` is right; deeper trees are not.

## What belongs where

| File | Use for |
|---|---|
| `common.json` | Strings identical in every context. If wording could differ per feature, it is not common. |
| `errors.json` | Last-resort HTTP/Prisma messages (`internal`, `conflict`, `notFound`). Filters use these when the resource is unknown. |
| `validation.json` | Generic constraint templates with `{property}`, `{value}`, `{constraints.0}`. |
| `<module>.json` | That module’s client-facing copy: not-found, conflicts, business rules, emails. |

Domain code uses `users.errors.notFound`, not `errors.notFound`.

## Rules

1. **Keys are IDs, not copy.** Never use English text as the key. Copy can change; the key must not.
2. **Do not reuse keys across contexts.** Unique key per meaning. `common` is the only reuse exception.
3. **Full sentences, named placeholders.** Never concatenate in TypeScript. Use `{name}`, `{count}` — not `{0}`. Adding a placeholder is a breaking change for every locale.
4. **Plurals** use nestjs-i18n objects and a `count` arg:

   ```json
   { "count": { "one": "{count} pending order", "other": "{count} pending orders" } }
   ```

   Include the categories the **target** language needs (`one` / `few` / `many` / `other`), not only English.

5. **English (`en/`) is the source of truth.** Other locales must mirror the same key tree.
6. **Translate client-facing text only.** Logs, stack traces, and Prisma internals stay English.
7. **Throw keys, not translated strings.** Store `I18nPath` + `args` with `i18nException`; translate in the filter so language stays request-scoped.

   ```ts
   throw new NotFoundException(i18nException('users.errors.notFound'));
   throw new BadRequestException(i18nException('orders.errors.invalidStatus', { status }));
   ```
8. **DTOs** use typed validation messages:

   ```ts
   @IsEmail({}, { message: i18nValidationMessage<I18nTranslations>('validation.IS_EMAIL') })
   email: string;
   ```

Enable `throwOnMissingKey: true` in development so a missing key fails fast.

## Avoid

| Avoid | Prefer |
|---|---|
| `common.userNotFound` | `users.errors.notFound` |
| Growing `errors.json` with every domain case | Module file + generic fallback in filters |
| One mega `messages.json` | One file per module |
| Keys that mirror UI copy | Stable intent names |
| Building sentences in TypeScript | One complete message per key |
